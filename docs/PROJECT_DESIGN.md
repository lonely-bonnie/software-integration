# Windows 软件集成中心项目设计

日期：2026 年 10 月 10 日。状态：整体设计与路线，首版 0.1.0 已实施。当前功能及尚未完成项以 [首版实现指南](IMPLEMENTATION.md) 和 README 为准。下文的 SQLite、告警事件、模块注册表、排序、导入导出、开机启动和桌宠均是后续设计。

软件定位为个人使用的 Windows 桌面工作台：从一个窗口打开常用网站，查看服务器流量和 Codex 额度，随着项目增加逐步添加模块。建议先实现可扩展的桌面主体和内置模块，再逐步增加数据源。桌宠在本阶段预留接口。

## 需求与范围

| 功能              | 初期行为                                                   | 后续扩展                                 |
| ----------------- | ---------------------------------------------------------- | ---------------------------------------- |
| 网站入口          | DigitalOcean 和 Tailscale 卡片，点击后用系统默认浏览器打开 | 自定义名称、图标、网址、分组和顺序       |
| DigitalOcean 流量 | 公网入站和出站速率、趋势、数据时间、连接状态               | 日月累计、阈值提醒、多 Droplet、计费对照 |
| Codex 额度        | 显示各额度窗口的剩余比例、官方重置时间和倒计时             | 消耗趋势、预计耗尽时间、提醒             |
| 模块管理          | 启用、停用、排序、配置，每个模块独立展示连接状态           | 更多官方 API 和开源服务适配器            |
| Windows 主体      | 主窗口、托盘入口、显式退出、配置保存                       | 便携发行、通知、更新、快捷键             |
| 桌宠              | 约定状态事件与打开模块的动作                               | 独立透明窗口、皮肤、动画和互动           |

暂按“DigitalOcean 使用 Linux Droplet、Windows 本机单用户、一个主要 Codex 账户”设计；这些是实施前要验证的条件。Tailscale 首版只作为网站入口和可选的私网连接通道，不承担自研 VPN 功能。

## 界面与使用方式

主窗口分为概览、模块管理和设置。概览上方放网站入口，下方放 DigitalOcean 和 Codex 监控模块。每张监控卡片显示数据来源、采样时间和连接状态，点击可展开趋势及配置。

推荐以概览卡片布局为默认，另提供紧凑列表布局，方便日常查看。入口卡片与监控卡片通过同一份模块注册表生成，不在页面中为每个服务单独堆放固定代码。

网站入口使用系统默认浏览器。这样可以延续现有浏览器登录和密码管理；将来确有需求再单独评估软件内嵌网页。主窗口关闭时可收起到托盘，托盘中提供明确的“退出”；开机启动由用户在设置中开启。

不把断线显示成零流量，也不把过期额度显示成实时额度。模块至少支持未配置、连接中、可用、数据过期、连接失败和已停用几种状态。演示模式始终显示“演示数据”。

## 分层结构

```text
Windows 桌面主体
  ├─ 主窗口 / 托盘 / 通知 / 设置 / 模块注册与布局
  ├─ 展示层：网站卡片 / 流量模块 / Codex 模块 / 后续桌宠视图
  ├─ 应用服务：刷新调度 / 缓存 / 数据质量 / 历史记录 / 阈值事件
  └─ 数据适配器
       ├─ 网站配置 → 系统默认浏览器
       ├─ DigitalOcean Monitoring API → 云端监控指标
       ├─ vnStat / 可选实时采样 → Tailscale 私网 SSH
       ├─ Beszel / Netdata → 已部署服务的 API
       └─ Codex App Server → 本机子进程的 stdio 协议

服务器侧的累计采集独立运行；Windows 端负责读取和展示。
```

采用单体程序中的清晰模块边界，首版内置可信模块。新增普通网站只需新增配置；新增监控数据源需要实现适配器及视图。模块之间通过公共服务和事件通信，避免直接引用彼此的内部代码。第三方任意代码插件、插件市场和热安装推迟到确有需求时再设计进程隔离与授权。

## 技术路线

首版确定使用 Electron、React、TypeScript。React 负责界面，Electron 主进程负责网络、凭据、受控 Codex 子进程和 Windows 功能。配置保存为 JSON，DO Token 使用 Electron safeStorage 的 Windows DPAPI；消耗预测样本先保存在内存。SQLite 历史留待后续累计功能接入。Tauri 保留为将来评估体积与资源开销的候选，不是当前构建依赖。

| 方案              | 适配情况                                 | 取舍                                                                   |
| ----------------- | ---------------------------------------- | ---------------------------------------------------------------------- |
| Tauri 2 加 React  | 适合自定义模块界面、托盘和将来的独立窗口 | Windows 开发需要 Rust、C++ Build Tools 和 WebView2；实际资源占用需测量 |
| Electron 加 React | Node 生态熟悉、开发和打包路径成熟        | 自带浏览器运行时，发行体积与常驻开销要实际评估                         |
| .NET 加 WPF       | Windows 原生窗口和托盘适配方便           | 卡片与图表生态及后续界面扩展要采用另一套实现                           |

当前优先使用已有 Node 工具链完成桌面验证。若以后迁移 Tauri，需要独立验证桌宠透明、点击穿透和多屏行为。[Tauri 开发依赖](https://v2.tauri.app/start/prerequisites/)，[托盘](https://v2.tauri.app/learn/system-tray/)。

本机已验证 Node 24、npm、Git，另已找到 Microsoft Build Tools 与 Codex CLI。Codex 不在当前 PATH，通过本机应用目录自动发现。未从当前 PATH 与通常 cargo 目录找到 Rust，因此本轮不添加 Rust 环境。Codex App Server 已成功返回真实账户额度窗口。

实施时使用项目锁文件和明确的工具路径，新增工具优先隔离配置。设计阶段没有修改已有 Python、Node、Codex、系统 PATH 或服务器。

## DigitalOcean 数据口径

流量模块必须区分四种数据，不能把它们相加成一个总数。

| 数据         | 建议来源                                   | 精度与限制                                                    |
| ------------ | ------------------------------------------ | ------------------------------------------------------------- |
| 云端监控速率 | DigitalOcean Monitoring API                | 官方返回 Mbps；实际采样时间和延迟须联调验证，首版按准实时展示 |
| 秒级网卡速率 | 持续读取选定网卡的字节计数，或 Netdata API | 目标 2 至 5 秒更新；需服务器端数据源及计数器异常处理          |
| 日月累计     | 服务器上的 vnStat 数据库与 JSON 输出       | 只覆盖采集开始后且记录完整的区间；电脑关机不影响服务器采集    |
| 官方计费流量 | DigitalOcean Billing 页面和支持的导出      | 团队级规则、更新节奏及过滤口径与单机网卡统计不同              |

Monitoring API 路径为 `/v2/monitoring/metrics/droplet/bandwidth`，按 Droplet ID、公私网接口、入站出站方向和时间范围请求。读取此接口需要 `monitoring:read`；自动列出 Droplet 时还需相应只读权限。初始轮询目标 30 至 60 秒，遇到限流按服务返回信息退避，不把更频繁的 UI 刷新称作更高采样精度。[官方接口](https://docs.digitalocean.com/reference/api/reference/monitoring/)。

默认提供 Mbps，另可切换 MB/s，按十进制单位换算：`1 MB/s = 8 Mbps`。累计数据保存原始字节，并明确显示 GiB 或 GB。所有记录包含来源、接口、方向、采样时间、获取时间和质量标记。

对当前规模，建议先用官方 API 接通监控；完整流量模块采用 vnStat 持续累计，并在确需秒级速率时加一个受限的网卡计数读取通道。Tailscale 可以承载 Windows 到服务器的私网连接。读数目标是指定公网接口，实际名称需检查路由和网卡；不能简单把 `tailscale0`、公网接口、VPC 和 Docker 网桥流量全部相加，否则可能重复统计。

秒级速率以两个采样的字节差除以时间差计算。接口消失、重启、计数下降或采样间隔异常时丢弃该次差值并标记中断。累计使用服务器数据库，不在 Windows 上仅靠实时速率积分形成月度事实。

DigitalOcean 官方说明 Droplet 的流量额度在团队内汇集，计费概览每天更新。因此软件显示的网卡累计标注“服务器观测累计”，不能作为官方账单承诺。没有完整历史时显示“自开始采集以来”或“本月记录不完整”；不能把缺失历史填成零。[DigitalOcean 流量计费](https://docs.digitalocean.com/platform/billing/bandwidth/)。

本月预测基于完整覆盖天数和观测平均值；不完整或样本不足时暂停预测。需要费用估算时，先获取或手工确认团队套餐、有效资源时长和计费周期，再建立单独的估算规则。首版保留打开官方 Billing 的入口。

## Codex 额度与重置时间

模块名称建议使用“Codex 额度”，其中分别显示官方重置倒计时和消耗预测。

Codex App Server 文档提供 `account/rateLimits/read` 与 `account/rateLimits/updated`，数据字段包括 `usedPercent`、`windowDurationMins`、`resetsAt`；后者为下一次重置的 Unix 秒时间戳。优先使用 `rateLimitsByLimitId` 的多额度桶结果，仅在缺失时兼容旧的 `rateLimits`。[官方 App Server 文档](https://developers.openai.com/codex/app-server)。

设计采用专用只读适配器，通过本机 Codex App Server 的 stdio 初始化协议查询，不启动推理任务。使用经发现的可执行文件路径，不把当前带版本哈希的目录永久写死。正式实现前根据该二进制生成或核对协议类型，并验证其登录身份与桌面用户的目标账户一致。当前聊天中的额度工具属于 Codex 环境能力，不能直接作为独立 Windows 软件的通用 API。

| 显示项     | 计算方式                               | 用户应如何理解                       |
| ---------- | -------------------------------------- | ------------------------------------ |
| 剩余比例   | `clamp(100 - usedPercent, 0, 100)`     | 当前账户及额度桶的服务端快照         |
| 下一次重置 | 服务端 `resetsAt` 转换到 Asia/Shanghai | 官方返回时间；随新快照更新           |
| 倒计时     | `max(0, resetsAt - 当前 UTC 时间)`     | 本机时间影响倒计时；到零后刷新确认   |
| 预计耗尽   | 当前桶近期正向使用增量与时间差估算     | 粗略趋势，任务复杂度变化会让结果变化 |

窗口长度由接口决定，不能永久写死为五小时和一周，也不能擅自把额度桶和某个模型一一对应。无字段、无权限或不支持的登录模式显示不可用，而不是零使用。账户或桶变化、发生重置、读数倒退、缺失点过多时重新开始预测；消耗为零或样本不足时不输出预计耗尽时间。

候选刷新策略为启动时读取、每 1 至 5 分钟刷新，并兼容服务端更新通知；这是一项设计参数，最终按账户接口延迟与限流验证调整。该模块不读取或改写 Codex 配置、对话数据库和令牌文件来推算额度，也不提供自动购买额度或自动兑换重置的操作。

## 模块协议与后续桌宠

每个模块声明 `id`、名称、版本、支持的主体 API 版本、类型、视图入口、配置结构和需要的能力。模块生命周期统一为初始化、启动、暂停、刷新和销毁。停用模块时取消定时器、请求和订阅，单个模块失败不会中断整个工作台。

数据服务统一输出：模块 ID、资源 ID、指标名、数值或空值、单位、采样时间、获取时间、来源、质量状态和错误分类。历史查询和最新快照由主体提供，模块不各自实现重复的后台常驻逻辑。

内置模块仅声明其实际需要的能力：例如 `website.open`、`metrics.read`、`notification.emit`。敏感网络请求和受限命令经过后端服务，不向页面提供任意 shell 执行入口。网络失败采用退避，通知采用阈值、持续时间和冷却期，避免波动时重复弹窗。

预留桌宠可订阅的事件：`module.status.changed`、`traffic.threshold.reached`、`codex.reset.confirmed` 和 `quota.low`。桌宠可调用 `app.show` 或 `module.open`，其外观与动画独立于数据适配器，不持有凭据，也不负责采集。重置确认事件在新快照确认后发出，不能仅凭本机倒计时归零宣布额度已恢复。

## 存储与连接

设置与布局保存在当前 Windows 用户的应用数据目录。SQLite 保存历史采样、累计快照、数据源实例和告警状态；默认先保留 30 天原始采样，较长历史按小时和日聚合，具体保留期可调整。

服务器累计以 vnStat 原数据库为事实来源，Windows 缓存只用于展示。请求窗口使用 UTC，界面使用 Asia/Shanghai；月度汇总的周期及时区必须与所选数据源一致并显示，不能直接按本机月份猜测官方计费边界。

网站配置可导入导出，导出文件不含凭据。DigitalOcean 使用最小只读权限。服务器连接优先使用已有 Tailscale 私网及专用只读身份；固定允许的查询，不提供任意远程命令。重连后补取可取得的历史，没有历史数据源的区间仍显示缺失。

## 开发顺序与验收

| 阶段           | 交付                                                      | 完成条件                                                                 |
| -------------- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 可行性验证     | 一个最小桌面窗口及真实只读数据样本                        | Electron 打包和托盘可用；DO 真实联调待用户配置；Codex 已读到官方额度窗口 |
| 首个可用版本   | 网站入口、模块管理、DO 准实时监控、Codex 倒计时、配置保存 | 安装后可运行；网站可打开；重启恢复布局；断线和缺字段不出现假数据         |
| 完整流量与提醒 | vnStat 累计、可选秒级速率、历史、简单阈值提醒             | Windows 离线期间服务器仍累计；明确采集开始时间、缺失区间及计费差异       |
| 扩展与桌宠     | 新模块示例及独立桌宠视图                                  | 新增模块无需修改主体业务；事件可被桌宠订阅；停用能释放资源               |

验证重点是数据真实性：用同一接口、方向和时间范围对照 DO 指标；用服务器 JSON 对照累计字节；验证 Codex 返回的账户、窗口和重置时间；测试断网、睡眠恢复、服务器重启、计数器回退和软件退出。监控必须在托盘状态和退出状态下表现符合设置，不能无声残留采集进程。

第一轮不同时部署 vnStat、Beszel、Netdata。先完成官方接口和本机额度的可行性验证，再根据秒级速率与月累计的实际需求选择服务器组件。若后续主要需求变为多服务器 CPU、内存和容器概览，则优先评估 Beszel 适配器。

## 实施前需要确认的信息

实施前需要服务器系统、Droplet 数量及 ID、可以使用的私网或 SSH 连接、已有采集工具、需要的实时更新间隔，以及 Windows 软件对应的 Codex 登录身份。凭据应通过软件或安全连接设置，不写入设计文档或聊天。

首版已实现网站入口、模块开关、DO Monitoring 适配器、Codex 官方读取、设置、托盘和便携打包。DO 账户权限与真实流量尚待用户配置后联调；服务器累计、睡眠恢复的完整验收、安装器和资源占用长期测量属于后续验证。
